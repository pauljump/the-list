- **bzr-bulk-triage**: Use when triaging or mutating many Bugzilla bugs from one query with bzr — "triage my open bugs", "close out the 5.x milestone", a weekly sweep. Stream the result set with --paginate --output ndjson, apply the read-before-write rule per row, and guard every mutation with --dry-run preview before the real write. ([randomparity/bzr](https://github.com/randomparity/bzr/tree/HEAD/content/skills/bzr-bulk-triage))
- **bzr-dependency-analysis**: Use when collecting and analyzing a bounded, deterministic Bugzilla dependency graph with bzr. ([randomparity/bzr](https://github.com/randomparity/bzr/tree/HEAD/content/skills/bzr-dependency-analysis))
- **bzr-dry-run-confirm**: Use when mutating Bugzilla data with bzr — preview every write with global --dry-run, verify the JSON payload with jq, then re-run without the flag to commit. Covers bug create/update/clone/resolve/close/reopen/dup, product/user/group create+update, component create and RHBZ-only update, batch previews via --from-json, exit-code triage, and --yes batch-confirm semantics. ([randomparity/bzr](https://github.com/randomparity/bzr/tree/HEAD/content/skills/bzr-dry-run-confirm))
- **bzr-file-bug**: Use when filing a new Bugzilla bug with bzr — discovers the right product and component, applies a template if available, and writes a well-formed report with a clear summary and reproduction steps. ([randomparity/bzr](https://github.com/randomparity/bzr/tree/HEAD/content/skills/bzr-file-bug))
- **bzr-project-manager-reporting**: Create a decision-ready project-management report from a Bugzilla Custom Search URL or saved bzr query, choosing safe CSV, XLSX, self-contained HTML, or Markdown output according to the artifact capabilities currently available. ([randomparity/bzr](https://github.com/randomparity/bzr/tree/HEAD/content/skills/bzr-project-manager-reporting))
- **bzr-reference**: Use when working with Bugzilla via the bzr CLI — viewing, searching, creating, or updating bugs, comments, attachments, products, or saved queries. Covers the command surface, the --json output contract, authentication, and the read-before-write rule. ([randomparity/bzr](https://github.com/randomparity/bzr/tree/HEAD/content/skills/bzr-reference))
- **bzr-release-readiness**: Review one Bugzilla release scope read-only and produce an evidence-backed readiness report when a release lead needs facts, assumptions, blockers, and limitations separated. ([randomparity/bzr](https://github.com/randomparity/bzr/tree/HEAD/content/skills/bzr-release-readiness))
- **bzr-release-tracking**: Use when driving a Bugzilla release milestone with bzr — "what's left for the 9.0 milestone?", checking which bugs drifted into or out of the release, rebalancing assignees and CC before the ship date, building a release-ready digest, or closing out the milestone once it ships. ([randomparity/bzr](https://github.com/randomparity/bzr/tree/HEAD/content/skills/bzr-release-tracking))
- **bzr-search-report**: Use when searching Bugzilla or producing a bug report/digest with bzr — run saved or ad-hoc queries, extract fields with --json and jq, and summarize results (e.g. "my open bugs", a weekly triage list). ([randomparity/bzr](https://github.com/randomparity/bzr/tree/HEAD/content/skills/bzr-search-report))
